# SP미디어텍 오디오북 제작 워크플로우 설계

원고 작업(대표) → 녹음 → Reaper 자동편집(안코디) → 검수 → 재녹음(픽업) → 마스터링/납품까지
**한 줄로 이어지는 제작 라인**의 설계 확정본. 2026-08 기준.

---

## 0. 한 문장 요약

> **원고 작업 단계에서 모든 대사에 부여되는 `대사번호`를,
> 녹음 파일명 → Reaper 아이템 이름 → 검수 리포트 → 픽업 요청 → 재녹음 반송 파일명까지
> 전 과정에서 유일한 키로 쓴다.**

지금 원고 파이프라인(`sp_pipeline.py`)의 `_검수목록.csv`에 이미 `대사번호`가 있다.
이 번호가 오디오 세계까지 넘어가는 순간, 아래 문제가 전부 기계적으로 풀린다.

| 지금의 문제 | 대사번호가 관통하면 |
|---|---|
| 오독/누락을 사람 귀로만 찾음 | 원고 텍스트 vs 음성인식(ASR) 텍스트를 번호 단위로 자동 대조 |
| 픽업 요청 시 "몇 페이지 몇째 줄…" 설명 | 번호 하나로 원고·톤 클립·타임코드가 전부 특정됨 |
| 재녹음본 끼워맞추기 수작업 | 반송 파일명의 번호로 원 위치 자동 펀치인 |
| 자동편집 오류를 어디서 났는지 모름 | 오류가 번호에 붙어 기록 → 자동화 재학습 데이터가 됨 |

## 1. 전체 흐름

```
[1] 원고 작업 (대표 · sp-audiobook-script)
     └─ 산출: 대사표시 PDF + 성우별 마스터 대본 + ★검수목록
     └─ 추가 산출(신규): _제작매니페스트.json  ← 오디오 자동화의 입력
          │
[2] 녹음 (성우별 개별 세션 · 파일명 규약)
          │
[3] Reaper 자동편집 (안코디 + Claude Code)
     └─ 매니페스트로 세션 자동 구성 → 숨소리/간격/레벨 자동 처리
          │
[4] 1차 자동 검수 (ASR 대조)
     └─ 산출: _오디오검수.csv (오독/누락/순서 의심 목록)
          │
[5] 2차 사람 검수 (청취 · Reaper 마커 규약)
     └─ 산출: 수정목록 (오류 유형 코드 포함)
          │
[6] 수정 루프
     ├─ 편집으로 해결(간격/레벨/숨소리/노이즈) → ReaScript 일괄 적용
     └─ 재녹음 필요(오독/누락/톤) → 픽업 요청서 + 톤 클립 자동 생성
          → 재녹음 반송 → 자동 펀치인 → 해당 구간만 재검수 (4로 복귀)
          │
[7] 마스터링 · 납품 QC (tools/delivery_qc.py)
     └─ 레벨/피크/노이즈플로어/길이/헤드룸 자동 판정 → 전부 ✓여야 납품
          │
[8] 메타데이터 · 납품 (sp-metadata 스킬)
```

**설계 원칙 3가지** — 원고 스킬의 철학을 오디오까지 확장한 것.

1. **판단은 AI, 확정은 사람.** 자동편집·자동검수는 "의심 목록"을 만들 뿐,
   납품 여부·재녹음 여부는 항상 사람이 확정한다.
2. **모든 판단은 파일(JSON/CSV)을 거친다.** 재현성·재검수를 위해
   중간 판단을 코드나 대화에만 남기지 않는다.
3. **발견된 모든 오류는 유형 코드와 함께 기록한다.** 이 기록이
   안코디의 Reaper 자동화와 대표의 원고 규칙을 계속 개선하는 학습 데이터다.

## 2. [1단계] 원고 작업 확장 — 제작매니페스트

원고 작업이 "오디오 편집 자동화까지 고려한 설계"가 되려면,
사람용 산출물(PDF·브리핑) 외에 **기계용 산출물 1개**를 추가하면 된다.

### `<원고>_제작매니페스트.json` (sp_pipeline.py에 `--manifest` 옵션 추가 제안)

기존 `_AI판단.json` + `_캐스팅.json` + `_음향목록.csv`에 이미 있는 정보를
오디오 자동화가 먹기 좋은 형태로 합쳐 내보내는 것이라 **추가 AI 판단 비용 0원**이다.

```json
{
  "book_code": "BANJJOK",            // 책 코드 (파일명 규약의 축)
  "chapters": [ {"no": 1, "title": "…", "line_range": [1, 87]} ],
  "cast": [ {"role": "메인(여)", "actor": "홍성우", "characters": ["내레이션","반쪽이"]} ],
  "lines": [
    {
      "id": 42,                      // = 검수목록의 대사번호. 전 과정의 유일 키
      "chapter": 3,
      "speaker": "소소리",
      "actor": "김성우",
      "text": "정말 그렇네요…",       // 원고 원문 (ASR 대조의 기준)
      "prev_gap_class": "tikitaka",  // 앞 대사와의 간격 클래스 ↓
      "tone_note": "장난스럽게, 살살 웃으며",  // 지문에서 추출한 톤 힌트
      "confidence": "high"
    }
  ],
  "sound_cues": [ {"line_id": 40, "type": "SFX", "desc": "펑!"} ]
}
```

### 간격 클래스 (`prev_gap_class`) — 자동 간격조절의 파라미터

안코디의 간격 자동화가 "일률적인 간격"이 아니라 **문맥별 간격**을 쓸 수 있도록,
원고 단계에서 각 대사 앞 간격의 성격을 분류해 준다. 원고에는 이미 이 정보가
(씬 전환, 화자 교대, 지문 길이 형태로) 다 들어 있다.

| 클래스 | 상황 | 권장 간격 (초기값, 안코디가 조정) |
|---|---|---|
| `tikitaka` | 같은 씬, 대사↔대사 즉답 | 0.3–0.5s |
| `beat` | 같은 씬, 지문 한두 줄 사이 | 0.7–1.0s |
| `scene` | 씬 전환 (음향목록의 씬 경계와 일치) | 1.5–2.5s + 페이드 지점 |
| `chapter` | 챕터 경계 | 2.5–4.0s |

간격 실제값은 매니페스트가 아니라 **Reaper 자동화의 설정 파일**에 둔다.
검수에서 "간격이 어색하다"는 지적이 쌓이면 설정값만 고치면 되고,
원고 쪽은 클래스 분류만 책임진다. (역할 분리 = 학습 루프의 핵심)

## 3. [2단계] 녹음 규약

성우별 개별 세션 녹음은 지금 방식 그대로. 규약만 확정한다.

- **폴더**: `<책코드>/01_원본녹음/<성우명>/`
- **파일명**: `<책코드>_<성우명>_S<세션>_<순번>.wav`
  (예: `BANJJOK_김성우_S1_003.wav`)
- **포맷**: 48kHz/24bit WAV 통일 (마스터링 때 납품 포맷으로 변환)
- 성우가 부스에서 **틀리면 즉시 그 문장 처음부터 다시** — 테이크 선별을
  자동화가 "마지막으로 완전하게 읽은 테이크" 규칙으로 처리할 수 있게 된다.

---

## 4. [3단계] Reaper 자동편집 (안코디 영역과의 접점)

안코디가 만들고 있는 자동화(숨소리 제거·대사 배치·간격·데시벨)는 그대로 발전시키되,
**입력을 매니페스트로 통일**하는 것이 이 설계의 요청 사항이다.

1. **세션 자동 구성**: 매니페스트로 Reaper 프로젝트 뼈대를 생성
   (ReaScript/Lua) — 트랙 = 성우, 리전 = 챕터, 마커 = 씬 경계·음향 큐.
2. **아이템 이름 = 대사번호**: 대사 배치가 끝난 아이템의 이름을 `L0042`처럼
   번호로 남긴다. 이후 검수·픽업·펀치인이 전부 이 이름으로 아이템을 찾는다.
3. 숨소리 제거·간격(클래스별)·데시벨 정규화는 안코디 자동화 담당.
   파라미터(간격 초기값, 숨소리 임계값, 목표 레벨)는 `reaper_config.json`
   하나에 모아 두고, 검수 결과에 따라 이 파일만 갱신한다.

> Claude Code + Reaper 연동은 ReaScript(Python/Lua) 스크립트를 Claude Code가
> 작성·수정하는 현재 방식이 맞다. 스크립트들을 이 레포 `tools/reaper/`에 모아
> 버전 관리하면 "학습시키면서 발전"의 이력이 남는다.

## 5. [4단계] 1차 자동 검수 — ASR 대조 (오독·누락 자동 발견)

**이 설계에서 ROI가 가장 큰 신규 요소.** 편집 완료된 오디오를
음성인식(Whisper 계열, 로컬 실행 무료)에 돌려 원고 텍스트와 대사번호 단위로 대조한다.

- 산출: `_오디오검수.csv`
  `대사번호 / 타임코드 / 유형 / 심각도 / 원고텍스트 / 인식텍스트 / 유사도`
- 감지 유형: **오독**(텍스트 불일치), **누락**(원고에 있는데 오디오에 없음),
  **중복**(같은 문장 두 번), **순서 바뀜**
- ASR도 한국어를 완벽히 받아쓰지 못하므로 유사도 임계값(예: 0.85) 이하만
  "의심"으로 올린다. → 사람은 전체가 아니라 **의심 행만** 들으면 된다.
- 원고 스킬의 ★(확인필요) 철학과 동일: 자동화는 확정하지 않고 ★만 단다.

---

## 6. [5단계] 2차 사람 검수 — 청취 규약

의심 목록 청취 + 전체 배속 청취(1.5–2x)를 하되, 발견한 오류를
**Reaper 마커로 그 자리에서 코드화**한다. 메모장 왕복이 사라진다.

**마커 이름 규약**: `ERR:<대사번호>:<유형코드>[:메모]`

| 코드 | 뜻 | 처리 경로 |
|---|---|---|
| `MIS` | 오독 | 재녹음 (픽업) |
| `OMI` | 누락 | 재녹음 (픽업) |
| `TON` | 톤/연기 방향 불일치 | 재녹음 (픽업) |
| `GAP` | 간격 어색 | 편집 (자동화 설정 조정 후보) |
| `LVL` | 레벨 튐/꺼짐 | 편집 |
| `BRE` | 숨소리 오제거/잔존 | 편집 (자동화 임계값 조정 후보) |
| `NOI` | 노이즈/잡음 | 편집 또는 재녹음 |

검수가 끝나면 마커를 내보내(ReaScript 한 줄) `_수정목록.csv`로 합친다.
1차 자동 검수 결과와 이 파일이 합쳐진 것이 **수정 루프의 유일한 입력**이다.

---

## 7. [6단계] 수정 루프 — "쉽게 고치는 법"

`_수정목록.csv`의 유형에 따라 두 갈래로 자동 분기한다.

### 7-A. 편집으로 해결 (GAP / LVL / BRE / NOI)

ReaScript가 수정목록을 읽어 해당 대사번호 아이템으로 바로 점프하는
**수정 내비게이션**을 제공한다 (다음 오류로 이동 단축키). 반복 유형은
일괄 처리(예: GAP 전체를 새 설정값으로 재적용). 수정 후 그 구간만 5단계 재검수.

### 7-B. 재녹음 필요 (MIS / OMI / TON) — 픽업 자동화

이 부분이 현재 가장 손이 많이 가는 곳이므로 3단계로 자동화한다.

**① 픽업 요청서 자동 생성** (성우별로 1개 파일)

```
[BANJJOK 픽업 요청 — 김성우님, 3건]

1. L0042 (3챕터, 오독)
   원고:  "정말 그렇네요, 소소리 님."
   현재:  "정말 그러네요…" 로 녹음됨
   톤:    장난스럽게, 살살 웃으며   ← 매니페스트의 tone_note
   참고음원: BANJJOK_PU요청_L0042.mp3  ← ② 톤 클립
```

**② 톤 레퍼런스 클립 자동 렌더**: 해당 대사의 **앞뒤 문맥 포함 구간**
(앞 대사 ~ 뒤 대사)을 편집본에서 자동으로 잘라 mp3로 렌더한다.
성우는 이 클립을 듣고 당시 톤 그대로 이어 붙을 수 있게 재녹음한다.
Reaper 아이템 이름이 대사번호이므로 구간 특정이 자동이다.

**③ 반송 → 자동 펀치인**: 성우가 `<책코드>_PU_<대사번호>_<성우명>.wav`
규약으로 보내면, 스크립트가 번호로 원 아이템을 찾아 교체하고
크로스페이드(10–20ms) + 앞뒤 대사와 레벨 매칭까지 수행한다.
교체 구간은 자동으로 4단계(ASR 대조) 재검수에 들어간다.

---

## 8. [7단계] 마스터링 · 납품 QC — `tools/delivery_qc.py` (구현 완료)

납품 직전, 추출된 최종 파일 전체를 자동 판정한다. **전 항목 ✓여야 납품.**

| 검사 | 기준 (기본값, `qc_config.json`으로 조정) |
|---|---|
| 평균 레벨 (Integrated Loudness) | -23 ~ -18 LUFS |
| 트루 피크 | ≤ **-3.0 dB** |
| 노이즈 플로어 | ≤ -60 dB |
| 파일 길이 | ≤ **70분** (초과 시 챕터 경계 분할 안내) |
| 시작 헤드룸(무음) | 0.5 ~ 2.0초 |
| 끝 헤드룸(무음) | 1.0 ~ 3.0초 |
| 포맷 | 샘플레이트/채널 규약 일치 |

```bash
# 폴더째 검사 → 표 + CSV 리포트, 하나라도 ✗면 종료코드 1
python3 tools/delivery_qc.py "납품폴더/" --csv 납품QC.csv
```

- 레벨/피크처럼 **게인만으로 고칠 수 있는 실패는 자동 수정 대상**으로 표시된다.
  (실제 수정은 Reaper/ffmpeg에서 — 판정과 수정을 분리해 사고를 막는다)
- **기준값 보정**: 기존에 문제없이 납품된 마스터 몇 개를 이 스크립트로 측정해
  나온 값으로 `qc_config.json`을 우리 회사 표준으로 확정할 것. (첫 실행 과제)
- 자동 판정 통과 후 **수동 스팟체크**: 각 파일의 처음 30초·마지막 30초·중간 1곳
  청취. 이것까지가 납품 게이트다.

## 9. 오류 학습 루프 — "계속 학습시키면서 발전"의 실체

모든 검수·QC 산출물(CSV)은 책별 폴더에 남기고, 책이 끝날 때마다
`오류로그.csv`에 한 줄씩 축적한다: `날짜 / 책 / 단계 / 유형코드 / 원인 / 조치`.

한 달에 한 번 이 로그를 Claude Code에 넣고 물으면 된다:
- `BRE` 오탐이 많다 → 안코디: 숨소리 임계값 조정
- 특정 클래스 `GAP` 지적 반복 → `reaper_config.json` 간격값 조정
- 특정 유형 화자 오배정 반복 → 원고 스킬 규칙 추가 (지금도 하고 있는 방식)
- 특정 성우의 `MIS` 패턴 → 마스터 대본에 발음 주의 표시 추가

**오류가 줄어드는 속도 자체가 관리 지표**가 된다.

## 10. 도입 로드맵 (우선순위 순)

| 단계 | 내용 | 효과 | 난이도 |
|---|---|---|---|
| **P1 (이번 주)** | 납품 QC 스크립트 사용 시작 + 기존 마스터로 기준값 보정 + 파일명/대사번호 규약 확정 | 납품 사고 즉시 차단 | 낮음 (완료) |
| **P2** | `--manifest` 출력 추가 + Reaper 아이템 이름 = 대사번호 + 마커 검수 규약 | 전 과정 ID 연결 | 낮음 |
| **P3** | ASR 자동 대조 검수 | 오독·누락 자동 발견 | 중간 |
| **P4** | 픽업 요청서 + 톤 클립 + 펀치인 자동화 | 재녹음 왕복 최소화 | 중간 |
| **P5** | Reaper 세션 자동 구성 + 간격 클래스 연동 | 편집 셋업 자동화 | 안코디 협업 |

각 단계는 앞 단계 없이도 독립적으로 가치가 있지만, ID 규약(P2)이 깔려야
P3–P5의 자동화가 전부 맞물린다.

## 11. 역할 분담

- **대표**: 원고 작업(+매니페스트), 캐스팅·검수 확정, 성우 픽업 커뮤니케이션, 납품 게이트
- **안코디**: Reaper 자동편집 고도화, 설정 파일 관리, 수정 루프 편집 처리
- **Claude Code**: 원고 판단, 스크립트 작성·유지보수, 검수 리포트 생성, 오류 로그 분석
