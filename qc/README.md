# 오디오북 검수 도구 (qc)

대본과 녹음을 대조해 성우의 **오독·누락·삽입**을 찾는다.

## 왜 만들었나

"음성 → STT로 받아쓰기 → 대본과 diff" 방식은 구조적으로 실패한다.
STT가 틀린 것과 성우가 틀린 것을 구분할 방법이 없기 때문이다.

낭독체 기준 CER을 넉넉히 5%로 잡아도:

| 항목 | 건수 |
|---|---|
| 3만 자 챕터의 STT 오인식 | 약 1,500건 |
| 실제 성우 오독 | 보통 수십 건 |
| **diff 결과 중 진짜 오류 비율** | **2~3%** |

게다가 한국어 STT는 띄어쓰기가 제멋대로라, 어절 단위로 비교하면 WER
(CER의 2~3배) 수준의 차이가 그대로 쏟아진다. 여기에 숫자·영문 표기 차이
("2024년" ↔ "이천이십사 년")가 더해진다.

이 도구는 두 단계로 그 문제를 푼다.

```
1단계 compare  대본과 STT를 같은 '읽기 형태'로 정규화한 뒤 음절 단위로 대조
               → 표기 차이에서 오는 가짜 오류를 걷어낸다

2단계 align    대본을 정답으로 주고 음성을 강제 정렬
               → 모델이 단어를 지어낼 수 없으므로 가짜 오류가 원천 차단된다
```

실측: 동봉 샘플 기준 어절 diff **17건 → 확인 대상 4건**(76% 감소), 심어둔
오독·누락·삽입 3건은 모두 탐지. 12만 자 합성 원고에서는 **7,740건 → 30건**
(99.6% 감소), 소요 1.4초.

---

## 1단계 — compare (지금 바로 쓸 수 있음)

이미 뽑아 둔 STT 결과 텍스트가 있으면 된다. **추가 설치 없음**(표준 라이브러리만 사용).

```bash
python -m qc compare --script 원고.txt --stt stt결과.txt --out out/
```

만들어지는 것:

- 콘솔 요약 — 기준선 대비 몇 건으로 줄었는지, 심각도별 분포
- `out/원고_검수.csv` — 엑셀로 여는 체크리스트. `확인` 열을 비워 뒀으니 검수자가 채운다
- `out/원고_검수.html` — 대본 위에 의심 구간을 표시. 브라우저로 바로 열린다

### 옵션

| 옵션 | 설명 |
|---|---|
| `--drop-parens` | 괄호 안 내용을 안 읽는 책일 때. 원어·한자 병기가 많으면 효과가 크다 |
| `--keep-hanja` | 한자를 그대로 두고 비교 (기본은 제거) |
| `--limit N` | 콘솔에 출력할 건수 (기본 40) |

`--drop-parens`는 **첫 챕터에서 어느 쪽인지 확인하고 정하라.** 성우가 안 읽는데
켜지 않으면 '누락'으로, 읽는데 켜면 '삽입'으로 잡힌다.

### 리포트 읽는 법

| 심각도 | 의미 |
|---|---|
| **높음** | 문장·문단 통째 누락, 4음절 이상 대치 — 먼저 볼 것 |
| **중간** | 짧은 대치, 3음절 이상 누락·삽입 |
| **확인필요** | 영문·외래어라 자동 판별 불가. 직접 들어봐야 한다 |
| **낮음** | 1~2음절 삽입·누락. 조사 탈락 등 STT 잡음일 가능성이 높다 |

---

## 2단계 — align (본질적 해결)

대본을 정답으로 주고 음성을 정렬한다. **STT 오인식이라는 노이즈원 자체가 없어진다.**
추가로 오디오 타임코드가 나오므로 DAW에서 바로 찾아갈 수 있다.

```bash
pip install -r qc/requirements-align.txt
python -m qc align --audio ch01.wav --script 원고.txt --out out/
```

만들어지는 것:

- `out/ch01_정렬.csv` — 타임코드가 붙은 체크리스트
- `out/ch01_정렬.json` — 단어별 (시작, 끝, 확률) 원본

### 검출 항목

| 사유 | 신호 |
|---|---|
| 낮은확률 | 대본대로 안 읽었을 가능성. 3단어 이상 연속이면 심각도 높음 |
| 긴무음 | 2초 이상 무음. 리테이크 흔적·문단 건너뜀 |
| 빠른낭독 | 문장 낭독 속도가 평균의 1.6배 이상 — 일부 건너뛰었을 수 있음 |
| 느린낭독 | 평균의 0.55배 이하 — 더듬음·반복 |

### 옵션

| 옵션 | 설명 |
|---|---|
| `--model` | Whisper 모델 (기본 `large-v3`). 먼저 `medium`으로 시험해 보길 권한다 |
| `--no-faster` | faster-whisper 대신 원본 whisper 백엔드 사용 |
| `--language` | 기본 `ko` |

GPU가 없으면 `large-v3`는 실시간의 몇 배가 걸린다. 한 챕터로 먼저 시간을 재 볼 것.

## 권장 운용 방식

1. **먼저 `compare`로 전체 챕터를 돌린다.** 설치가 필요 없고 몇 초면 끝난다.
   여기서 나온 '높음' 항목만 들어봐도 대부분의 실제 오독이 잡힌다.
2. 정밀도가 더 필요하면 `align`을 추가한다. 타임코드가 붙어 검수 속도가 다시 크게 준다.
3. 두 결과를 함께 보면 확신도가 올라간다 — 양쪽에서 동시에 걸린 지점이 진짜다.

### 고유명사 사전 활용

STT를 뽑을 때 등장인물 이름·지명을 `initial_prompt`로 넣으면 인식률이 크게 오른다.
`sp-audiobook-script` 작업에서 만든 **등장인물표를 그대로 재활용**하면 된다.

```python
model.transcribe(audio, language="ko",
    initial_prompt="등장인물: 김서준, 박하늘, 이도연. 배경: 조선 후기 한양.")
```

## 한계 (알고 쓸 것)

- **영문 고유명사**는 한글 표기를 기계적으로 알 수 없다. `Michael`을 '마이클'로
  읽었는지 판별할 수 없으므로 `확인필요`로만 표시하고 판단하지 않는다.
- **한국어 수사는 문맥 의존적**이다("3번" = 세 번/삼 번). 가능한 읽기를 모두
  후보로 두고 하나라도 맞으면 통과시킨다. 가짜 오류를 줄이는 대신, 드물게
  진짜 숫자 오독을 놓칠 수 있다.
- 삽입이 숫자 바로 옆에서 일어나면 유형이 `삽입` 대신 `대치`로 표시될 수 있다.
  위치와 내용은 정확하므로 검수에는 지장이 없다.
- `align`은 **실제 음원으로 아직 검증하지 않았다.** 분석 로직(`find_suspects`)은
  합성 데이터로 점검했지만, stable-ts 정렬 자체의 한국어 품질은 대표님 음원으로
  한 챕터 돌려 보고 판단해야 한다.
- 단어 단위 타임스탬프 정밀도가 더 필요하면 **Montreal Forced Aligner**(공식
  한국어 음향모델 v3.0.0 제공)가 더 정확하다. 설치가 무거운 대신 정밀도가 높다.

## 점검

```bash
python qc_selftest.py     # 음원·모델 없이 실행. compare 전 구간 검증
```

## 구조

```
qc/
├── normalize.py   한국어 정규화 — 숫자·영문 읽기 변환, 변이형 생성, 원본 위치 매핑
├── compare.py     음절 단위 정렬(앵커 기반) + 변이형 억제 + 오류 분류
├── align.py       강제 정렬 래퍼(stable-ts) + 의심 구간 검출
├── report.py      콘솔 / CSV / HTML 출력
├── __main__.py    CLI
└── samples/       동작 확인용 샘플 대본·STT (오독·누락·삽입이 심어져 있음)
```
